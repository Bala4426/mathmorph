# Decisions made without asking

Each entry records the decision, the reason, and the safer alternative that was rejected (if any).

## Environment

- **D1 — .NET 8 SDK installed locally.** The machine has the .NET 9 and 10 SDKs/runtimes but not .NET 8. The .NET 8 SDK (8.0.428) was installed with Microsoft's `dotnet-install.ps1` into `D:\eq\eqconv\tools\dotnet8` (`-NoPath`, no system change). This took 1 min 52 s.
- **D2 — MathMorph.exe is published self-contained (win-x64).** No system-wide .NET 8 runtime exists, and installing one would change the system. `bin\MathMorph.exe` therefore carries its own .NET 8 runtime. Engine source uses built-in libraries only (no PackageReference in `src\MathMorph.csproj`).
- **D3 — No real samples in `D:\eq\input`.** The folder did not exist. It was created and is empty: no real samples were available there. One real document was found at `D:\eq\real_sample_manuscript.docx` (SHA-256 `DC016E1D…E065FC`). It is processed by its explicit path, read-only, and was not copied into the input folder.
- **D4 — pix2text dependency pin.** pix2text 1.1.7 pulls rapidocr 3.10.0, which lacks a function that cnstd 1.2.8 imports (`resolve_model_key`), so import fails. rapidocr was pinned to 3.9.2 (cnstd requires ≥3.9.1). With the pin, import works.
- **D5 — Model download through the Windows certificate store.** The network intercepts TLS, so Python's certifi bundle rejected Hugging Face. The one-time download (`scripts\download_models.py`) uses `truststore` (Windows certificate store) and does not disable verification. Models are stored in `tools\models`. Workers then run with `HF_HUB_OFFLINE=1`.
- **D6 — Library caches redirected into the project.** `YOLO_CONFIG_DIR`, `HF_HOME`, `CNSTD_HOME` and `CNOCR_HOME` point into `tools\models`. One exception: before the redirect existed, the first `import pix2text` created `%APPDATA%\Ultralytics\settings.json` (a 450-byte settings file from a dependency). It was left in place (deleting user files is not in scope).
- **D7 — Recognition model.** Only the pix2text formula recognizer is used (`LatexOCR(model_name="mfr-1.5", model_backend="onnx", device="cpu")`). The images are already cropped equations, so text/layout models are not needed.
- **D8 — Pandoc source.** Pandoc 3.9 comes from the pip wheel `pypandoc_binary` (a pip package download, which the brief allows) and is copied to `tools\pandoc\pandoc.exe`.

## Detection

- **D9 — Picture element definition.** A picture element is one of: a `w:drawing` with its own `a:blip` (shapes/text boxes without a blip are not pictures); a `w:pict` with its own `v:imagedata`; or a `w:object` (OLE). A drawing nested inside `w:object` is that object's preview and is not counted separately. Text-box content (`w:txbxContent`) is excluded when looking for "own" blips, so a text box's inner picture is counted once, in the text box.
- **D10 — Category priority.** NATIVE (picture inside m:oMath) > container (header/footer/footnote/endnote/comments) > mc:Fallback > anchored/floating VML > no image data > EMF/WMF > taller than 1 inch > other non-PNG/JPEG format > logo/figure by name/alt text > OLE_PREVIEW / CANDIDATE. After recognition, an image whose content looks like a logo/figure/photo is moved to EXCLUDED: more than 5% saturated pixels, or more than 30% mid-gray pixels.
- **D11 — Footnotes, endnotes and comments are excluded containers.** The rules list body, table cells and text boxes as candidate containers and say nothing about notes and comments. Excluding them is the conservative choice.
- **D12 — EMF/WMF are always UNSUPPORTED_FORMAT.** OOXML has no standard link from an EMF/WMF picture to a PNG preview of it. Guessing by file name could pair the wrong image, so no such pairing is made.
- **D13 — Paragraph index** = 0-based index of the containing `w:p` among all `w:p` elements of that part in document order. This includes paragraphs in tables, text boxes, and both mc:Choice and mc:Fallback copies. It does not change after conversion, because paragraphs are never added or removed.

## Conversion

- **D14 — LaTeX→OMML via Pandoc.** MML2OMML.XSL is not installed (no Microsoft Office). Pandoc (texmath) writes OMML directly. A conversion is accepted only if Pandoc produces exactly one `m:oMath` and no leftover text runs; leftover runs mean Pandoc could not parse part of the TeX. The OMML is then validated: math-namespace elements only, from a whitelist, and non-empty.
- **D15 — Splicing, not re-serialising.** The changed XML part is edited by replacing the exact character span of each converted run. The span is located from parser line info and verified by element name. Every other byte of the part stays as it was, and the encoding and BOM are preserved. The result must re-parse with the hardened parser or nothing is written.
- **D16 — Namespace.** The inserted `m:oMath`/`m:oMathPara` declares `xmlns:m` locally, so the root element (with its namespace list and mc:Ignorable) is never touched.
- **D17 — Picture in a run-level mc:AlternateContent Choice.** The run is replaced by a paragraph-level `mc:AlternateContent`. Its Choice holds the equation, using the original Choice start tag and Requires value. Its Fallback holds a run with the original Fallback content, copied verbatim with the original run start tag and rPr.
- **D18 — Not converted in place (left as picture, NEEDS_REVIEW):** pictures inside tracked changes (`w:ins`/`w:del`/`w:moveFrom`/`w:moveTo`), because WordprocessingML cannot hold an `m:oMath` there; runs that hold other content besides the picture; and run parents other than `w:p`, `w:hyperlink`, `w:sdtContent`, `w:smartTag`, `w:customXml` and `w:fldSimple`, or a paragraph-level mc:Choice.
- **D19 — Alt text.** OMML has no alt-text attribute, so the picture's `wp:docPr` description cannot be carried onto the equation. The original image part and its relationship stay in the package unchanged (the relationship becomes unused). report.csv records the relationship ID and SHA-256, so every equation can be traced back to its source picture.
- **D20 — Display vs inline.** `m:oMathPara` is used only when the paragraph has no other visible content and the run's parent is the paragraph itself. Otherwise the equation is an inline `m:oMath` at the same position. Visible content means text, tab, symbol, break, field, note reference, another picture or another equation.
- **D21 — Output on gate failure.** If any Gate 3 check fails, the output is renamed `<name>.GATE3_FAILED.docx`, so it cannot be mistaken for a good result. The input is never touched.
- **D22 — Overwrite protection.** A document whose output subfolder already has files is skipped (SKIPPED_EXISTS) unless `--force` is given. Without `--force`, BATCH_SUMMARY.md and review\index.html are written with a timestamp suffix rather than overwriting.
- **D23 — Input/output separation.** In folder mode, the output folder may not be the input folder or inside it. In single-file mode, the output folder may not be the file's own folder. In every mode, the output file may not equal the input path.
- **D24 — Work files.** Extracted images, renders and LibreOffice PDFs go to `<output>\_work\<doc>\`. These are local only and support the review page.
- **D25 — CSV injection guard.** CSV cells starting with `= + - @` get a leading apostrophe inside the quotes. This applies only to the report; the .docx is unaffected.
- **D26 — Logging.** report.csv contains no document text except the recognised LaTeX. docPr names and descriptions are not logged.

## Verification

- **D27 — Renderer.** No LaTeX/dvipng and no Node.js are installed. Microsoft Edge is installed, and Chromium has rendered MathML Core natively since version 109. Rendering is therefore LaTeX → MathML (local Pandoc) → headless Edge screenshot of a local `file://` page, with no external resources and with background networking, component updates and sync disabled. Edge uses its own profile in `out\edge_profile`.
- **D28 — Score definition.** Both images are cropped to ink (gray < 200), resampled to 32 px height with the original's aspect ratio, and blurred with σ=1.5. The score is SSIM from scikit-image (Gaussian weights, 7-px window). Display and inline renderings are both tried and the higher score is kept. Chosen from a measured pilot on 10 synthetic pairs (scratch experiment, matplotlib DejaVu originals vs Edge Cambria Math renders). Several variants were tried; none separated correct from wrong LaTeX. With this variant, correct renders scored 0.384–0.786 and deliberately wrong LaTeX scored 0.175–0.614; correct beat wrong in 8 of 10 pairs. SSIM across different fonts is therefore weak evidence, and the threshold rule in the brief stops it from accepting errors.
- **D29 — Open XML validator** is a separate verification tool (`tools\OoxmlValidator`, Open XML SDK NuGet package). The engine has no NuGet dependency; it calls the validator as an external process. Gate criterion: the output has no validation errors that the input did not already have. Errors already in the input are reported, not counted against the converter.
- **D31 — Threshold = 0.95 (fallback).** The visual sample had a MISMATCH at SSIM 0.811 and only 3 items above it, too few to decide. The brief's fallback was applied. Consequence: no equation in the real document is converted automatically; all 123 are NEEDS_REVIEW, with their recognised LaTeX listed in review\index.html. A lower threshold can be chosen with `--min-score` after a larger, human-labelled sample.
- **D32 — Mechanics validation run.** Under the official threshold nothing is converted, so Gates 3 and 4 would pass trivially. To test the converter itself, a separate run with `--min-score 0` was made into `out\mech_*`. It is evidence only, not a deliverable. It found and fixed one real defect (D33).
- **D33 — OMML schema-order normalisation.** Pandoc writes `m:mcPr` as (mcJc, count), while the schema requires (count, mcJc). The Open XML validator caught this. `OmmlConverter.Normalize` reorders the children of `m:mcPr` and `m:mPr` into schema order before validation.
- **D34 — Corpus outputs stay inside the project** (`out\official_corpus`), so synthetic documents are not mixed with the user's real output in `D:\eq\output`.
- **D35 — Recognition rate denominator.** Images excluded as logos/figures by their content statistics are not counted as recognition attempts.
- **D36 — SKIPPED_EXISTS writes nothing.** A document skipped because its output folder exists (no `--force`) leaves that folder completely untouched. This bug was found by the docs subagent and fixed.
- **D37 — The OLE_PREVIEW status value is not used for decisions.** OLE previews are recorded with category OLE_PREVIEW in report.csv. Their status is CONVERTED or NEEDS_REVIEW like any other candidate, so the report shows both facts.
- **D38 — "Convert everything and proofread" (user request, 2026-11-11).** The real document was converted with `--min-score 0`. Every converted equation was proofread against its picture. Wrong or unconvertible items were corrected through the new `--latex-overrides <csv>` option (sha256,latex; human-supplied LaTeX bypasses recognition and the score threshold, but not the structure, OMML or gate checks). That run exposed a second Pandoc schema issue: `\text{}` emits `m:nor` and `m:sty` together, which the schema forbids. `Normalize` now drops `m:scr`/`m:sty` when `m:nor` is present; a regression test was added. Final output: 123/123 converted, all Gate 3 checks PASS. Details are in PROOFREAD.md next to the document.
- **D30 — Unit tests** use a small hand-written test runner (no xunit/NUnit packages). It writes `tests\unit_result.json`, which Gate 3 reads.
